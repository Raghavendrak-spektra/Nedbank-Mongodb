## Question
You have completed all recovery steps and functional verification tests, confirming that mongod is active, enabled, and serving customer360 data successfully. Now you create an incident note documenting: symptom, diagnosis, checks used, recovery action, and verification results. Why is it important to save this structured incident evidence in `/opt/cloudlabs/mongodb-customer-data/evidence/m6-incident-note.txt` rather than simply announcing verbally that the issue is fixed?

## Options
Option 1 : Incident notes are required by MongoDB licensing agreements but have no operational value.

Option 2 : Written documentation is only required for audit purposes and does not affect operational recovery.

Option 3 : Documentation is a waste of time; as long as the service is running, there is no need for any record.

Option 4 : Structured incident records serve multiple purposes: they preserve evidence for post-incident review, enable root cause analysis to prevent recurrence, provide a historical record for the organization, and allow the validation system to confirm that proper troubleshooting procedures were followed.

## Answers
Option 4 : 1

## Correct Answer Feedback
Option 4 is correct
